По мере роста программы увеличивается не только количество строк кода, но и количество модулей. В небольших проектах десятки файлов еще можно держать в одной директории, но в реальных приложениях файлов могут быть сотни и тысячи.

Чтобы организовывать модули в более крупные логические группы, в Python используют пакеты. В этом уроке мы работаем с обычными пакетами. Обычный пакет представляет собой директорию с файлом _\_\_init\_\_.py_ и модулями Python. Файл _\_\_init\_\_.py_ может быть пустым.

Например, структура проекта может выглядеть так:

```text
project/
├── main.py
├── payments/
│   ├── __init__.py
│   ├── stripe.py
│   └── paypal.py
└── users/
    ├── __init__.py
    ├── auth.py
    └── profile.py
```

В этом примере `payments` и `users` являются пакетами, а `stripe.py`, `paypal.py`, `auth.py` и `profile.py` — модулями.

Пакеты помогают группировать код по задачам и упрощают навигацию по проекту. Вместо сотен файлов в одной директории код разделяется на отдельные области ответственности.

## Импорт из пакета

К модулям внутри пакета обращаются через точку:

```python
import payments.stripe
```

После импорта можно использовать содержимое модуля:

```python
import payments.stripe

payments.stripe.create_payment()
```

Точка показывает путь внутри пакета. Python последовательно переходит от пакета к модулю.

## Импорт конкретного модуля

Обе формы импорта загружают модуль `payments.stripe`. Форма `from payments import stripe` связывает его с коротким именем `stripe` в текущем файле.

```python
from payments import stripe

stripe.create_payment()
```

Сокращается обращение к функции, `stripe.create_payment()` вместо `payments.stripe.create_payment()`. Сам импорт при этом может занимать больше символов.

## Вложенные пакеты

Пакеты могут содержать другие пакеты:

```text
project/
└── app/
    ├── __init__.py
    └── payments/
        ├── __init__.py
        ├── stripe/
        │   ├── __init__.py
        │   ├── client.py
        │   └── api.py
        └── paypal.py
```

В этом случае путь к модулю становится длиннее:

```python
from app.payments.stripe import client
```

Такая структура часто встречается в больших проектах. Она помогает разделять код на независимые части.

## Пакеты и пространства имен

Пакеты создают дополнительный уровень пространства имен. Благодаря этому разные части программы могут содержать модули с одинаковыми именами.

Например:

```text
project/
├── admin/
│   ├── __init__.py
│   └── config.py
└── user/
    ├── __init__.py
    └── config.py
```

Здесь существуют два разных модуля `config.py`.

Python различает их по полному пути:

```python
import admin.config
import user.config
```

Без пакетов такие имена конфликтовали бы между собой.

## Файл инициализации пакета

Файл _\_\_init\_\_.py_ обозначает обычный пакет. Он нужен и тогда, когда внутри нет общего кода. В этом случае файл оставляют пустым.

```text
payments/
├── __init__.py
├── stripe.py
└── paypal.py
```

Каталог может хранить любые файлы. Наличие _\_\_init\_\_.py_ делает `payments` обычным пакетом, к модулям которого обращаются по именам `payments.stripe` и `payments.paypal`. При импорте `payments` Python выполняет код из _\_\_init\_\_.py_. В нём можно определить имена, доступные через пакет.

У Python также есть namespace-пакеты. Они позволяют объединять части одного пакета из нескольких каталогов и обходятся без _\_\_init\_\_.py_. Это отдельный способ организации пакетов. Для обычных пакетов из примеров этого урока файл создаётся в каждом каталоге пакета, в том числе во вложенных.

## Имена пакета в \_\_init\_\_.py

Через `__init__.py` пакет собирает функции своих модулей в одном месте. Код снаружи обращается к ним через имя пакета, и ему не нужно знать, в каком модуле лежит каждая функция. Внутри `__init__.py` модули пакета импортируются по полному пути от имени пакета, так же как из любого другого файла проекта. Короткая запись `import stripe` здесь не сработает, и Python ответит ошибкой `ModuleNotFoundError: No module named 'stripe'`.

Пусть функция `create_payment()` в модуле `stripe` возвращает строку `"stripe payment"`, а функция с тем же именем в модуле `paypal` возвращает `"paypal payment"`. Если импортировать обе под именем `create_payment`, второй импорт перекроет первый. Поэтому в `__init__.py` каждой функции дают свое имя с помощью `as`.

```python
# payments/__init__.py
from payments.paypal import create_payment as create_paypal_payment
from payments.stripe import create_payment as create_stripe_payment
```

В этом коде `as` задает имя, под которым импортированная функция доступна в модуле. Функция `create_payment()` из `payments.stripe` становится `create_stripe_payment()`, а функция из `payments.paypal` становится `create_paypal_payment()`. Теперь файлу _main.py_ достаточно импортировать сам пакет.

```python
# main.py
import payments

print(payments.create_stripe_payment())  # => stripe payment
print(payments.create_paypal_payment())  # => paypal payment
```
